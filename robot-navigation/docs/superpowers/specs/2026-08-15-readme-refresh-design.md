# Robot Navigation README Refresh

## Audience

The primary reader is a robotics developer who wants to clone the repository,
run the app, and understand its main workflows without first reading the
implementation.

## Structure

The README will lead with the app outcome and a short feature summary, followed
by the Docker quick start. It will then explain the control panel workflow,
commands, stored data, and architecture. Native macOS, extension reuse, and
maintainer deployment will appear later as secondary material.

## Style

- Use short, direct sentences and natural technical language.
- Do not use em dashes.
- Keep the document compact and avoid repeating the same behavior.
- Include placeholders for a future hero image and demo GIF.
- Prefer links to focused documentation over long explanations.

## Accuracy

The README must match the current lifecycle commands, House and Warehouse
simulation choices, Waffle Pi robot, Dashboard layout, mapping workflow,
waypoint behavior, navigation status, local data boundaries, and shared asset
catalog.

## Out of Scope

Creating the hero image or GIF is a separate backlog item. Distribution,
release packaging, and simulation-to-real guidance remain deferred.
